# 03 · 图片/PDF 附件与 transcript 内联图使用说明（面向用户）

> 上位文档：[`../image-attachments.md`](../image-attachments.md)
> 这一页只讲「怎么用、有什么限制」。为什么这么实现见 [`01`](01-placement-decision.md) 与 [`02`](02-storage-and-gc.md)。

---

## 怎么添加附件

三种方式：

### 1. 剪贴板粘贴（Ctrl/Cmd+V）

- 截图后直接按 **Ctrl/Cmd+V** 粘贴到输入框
- 不需要先把截图保存成文件 —— 截图工具把数据放进剪贴板就够了
- 支持一次粘贴多张
- **PDF 也支持直接粘贴**
- 图片和 PDF 可以混着一起粘贴；不支持的内容会继续按普通文本处理

### 2. 从项目里拖进来

- 在 VS Code 资源管理器里选中附件，**按住 Shift** 拖进输入框
- 支持 PNG、JPEG、GIF、WebP、SVG、PDF

### 3. 文件选择器

- 点输入框的 **+**（Attach）按钮选文件，支持多选
- 图片会显示缩略图；PDF 会显示 `PDF` 方块

---

## 缩略图条

添加成功后，附件会显示在输入框上方：

- **图片** —— 48px 缩略图
- **PDF** —— 48px 的 `PDF` 方块，不显示长文件名
- **横排滚动** —— 多个附件不换行，横向滚动
- **悬停 / 键盘聚焦** —— 显示高亮环；可以 Tab 逐个走到每个附件
- **删除** —— 右上角 ×，或聚焦后按 Delete
- **打开**：
  - 图片：点击缩略图，打开图片预览
  - PDF：点击方块，在编辑器里打开原文件（如果本地路径仍然可用）

**PDF 方块的 hover**：会显示完整本地路径。这样列表保持短小，但你仍然能确认它到底是哪一个文件。

**失效附件**：如果某张图的数据已经不在磁盘上了（比如手动清理过 `~/.tomcat`，或草稿在另一台机器上打开），那张缩略图会显示为失效状态并附一个移除按钮，**草稿的其余部分不受影响** —— 文字和别的图片都还在。

---

## 图片预览

点任意缩略图（未发送的或历史消息里的都可以）会打开一个独立的编辑器标签：

| 操作 | 方式 |
|---|---|
| 缩放 | `+` / `-` 按钮或快捷键；`0` 适应窗口 |
| 翻页 | ←/→ 按钮、键盘方向键、或点底部缩略图条 |
| 复制 | ⧉ 按钮。剪贴板不接受原格式时会自动转成 PNG |
| 另存为 | ↓ 按钮 |
| 关闭 | Esc 或 ✕ |

预览用的是**原始全尺寸图片**，不是放大的缩略图，所以放大后是清晰的。

**注意**：PDF 不走这个预览面板。PDF 的点击行为是“打开文件”，不是“图片放大”。

## Transcript 里的本地内联图片

assistant 的正文里，只有一种写法会直接显示成图片：

```md
![草图](docs/mockup.png)
```

显示规则：

- 鼠标悬浮在图上会变成放大镜光标
- 点击图片会弹出一个轻量大图层
- **按 `Esc`** 或 **点击图片外的遮罩** 会关闭
- 点击放大的图片本体**不会**关闭，只是避免误触

下面这些情况**不会**显示成图片：

```text
`docs/mockup.png`
  -> 这只是文件路径，仍然是可点击文件链接

![图](https://example.com/mockup.png)
  -> 远程 URL，不渲染

![图](/Users/you/Desktop/private.png)
  -> 不在当前工作区，也不在系统临时目录，不渲染
```

当一张图不满足显示条件时，界面会退回成一个可点击的路径文本，而不是画出一个坏掉的图片框。

## 草稿会保留到什么程度

未发送的内容（文字 + 图片/PDF 附件）会自动保存。以下情况**都能恢复**：

```text
  切到别的会话再切回来        ✓
  webview 重新加载            ✓
  扩展重启                    ✓
  VS Code 完全退出重开         ✓
  tomcat 后端进程崩溃或升级    ✓   ← 草稿不依赖后端健康
```

**草稿跟着工作区走。** 同一个工作区的两个窗口如果同时编辑同一个会话，后保存的那份会覆盖先保存的（和 VS Code 自己的聊天输入框行为一致）；不同工作区的窗口互不影响。

草稿文件在扩展的存储目录下（`composer-drafts/<会话 id>.json`），里面**只有文字和附件引用，没有图片/PDF 数据本身** —— 所以它很小，打字时的保存开销可以忽略。

### 升级注意

**从旧版本升级后，未发送的草稿会被清空一次。** 旧版本把草稿存在后端的另一个位置，这次改动没有做数据迁移（草稿是临时内容，为一次性格式变更写迁移代码不划算）。升级后新写的草稿一切正常。

## 格式与大小限制

| 类型 | 支持格式 | 单个上限 |
|------|---------|---------|
| 图片 | PNG、JPEG、GIF、WebP、SVG | 4.5 MB |
| 文件 | PDF | 25 MB |

**SVG 的特殊处理**：模型的视觉接口不认 SVG，所以添加 SVG 时会在本地转成 PNG 发给模型，派生 PNG 的长边最多 2048px、保持比例；而**你在界面里看到的仍然是原始 SVG**（原件及另存字节不变，矢量渲染）。同次粘贴按顺序处理，避免同时展开多张大图。如果转换失败，会退而把 SVG 源码作为文本发给模型 —— 对图标和 logo 这类内容，模型读源码往往比看图更准。源码超过 50KB 时不内联。

## 模型兼容

- 图片总是会随消息发送给后端
- PDF 也总是会随消息发送给后端
- 如果当前模型不支持视觉输入，添加图片时会有提示，但图片仍然保留在草稿里（换个模型就能直接发）

## 附件发不出去时会看到什么

先分清两种情况，它们的提示不一样：

### 1. 发送前就知道“这个模型不支持”

这是**能力表里明确写着不支持**的情况，比如当前模型没开 vision / files。

- 输入框里会直接出现中文提示
- 这条消息**不会**写进 transcript
- 附件还留在草稿里，你可以：
  - 切到支持该能力的模型再发
  - 或者手动删掉附件，只发文字

### 2. 能力表说支持，但端点这一刻临时不接受

这是这次整改重点修掉的那类情况。比如第三方中转偶发拒绝了 `input_file` / `input_image`。

你会依次看到：

```text
第一次拒绝
  -> 自动重试

第二次还是同类拒绝
  -> 再自动重试一次
  -> 同时出现一条 notice：
     “本轮附件未被当前端点接受，已按纯文本发送”
```

这条 notice 的意思不是“附件丢了”，而是：

- 这次请求会继续完成
- 只是模型收到的是占位文本，不再是原始图片/PDF 数据
- transcript 里的原始附件账本仍然保留，不会被这次临时降级改写

### 3. 什么情况下才会看到红字

只有下面两类情况才会直接变成红字：

- **重试预算已经耗尽**，端点还是拒绝
- **确定性拒绝**，比如内容安全拦截（`content_filter`），这种重发也不会变好

也就是说，**一次偶发抖动不会再像以前那样立刻把整轮对话判死**。系统会先自愈，再决定要不要报错。

## 历史消息里的附件

- 已发送消息里的图片会随会话历史一起恢复
- 已发送消息里的 PDF 也会显示为同样的 `PDF` 方块
- 历史图片：点击可再次预览、另存为（不能删除 —— 历史是不可变的）
- 历史 PDF：hover 显示完整路径；本地路径还在时可点击打开原文件
- 删除会话时，它的草稿和历史一起清理

**关于磁盘占用**：附件数据存在 `~/.tomcat/…/sessions/attachments/` 下。只有 `thumbs/` 缩略图是可重建缓存，默认容量预算为 256 MiB。`blobs/` 中被历史消息引用的原件可能是唯一副本，**不要手工删除，不能承诺自动恢复**。未发送草稿依靠默认 7 天的租约保护，重新加载草稿会续期；长期未使用且租约已过期的附件，若也没有历史引用，可能在宽限期后被 GC 清理。请另行保存需要长期保留的重要原件。
