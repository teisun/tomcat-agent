## Design boundaries

Follow the approved plan: independent Rust JSON and typed TS catalogs; current-language-to-English fallback; ordinary Chinese keys required, `term.*` optional. Uninitialized library callers default to English; application entrypoints still resolve auto/host/system/saved preferences. Technical terms remain English this release. Fixed terms have keys; open identifiers (tool/model/provider IDs, paths, commands) remain data. User-facing controls, actionable errors and accessible names are localized. Model instructions/tool feedback and developer diagnostics stay fixed English outside the catalogs. Decisions use codes, IDs, enums and explicit paths, never rendered wording.

Tests use English source-catalog expectations. Chinese resources are checked for key coverage, nonempty values and matching placeholders; Chinese-mode UI tests use stable nodes and behavioral receipts. Existing HEAD-English contract assertions remain unchanged. Unicode input and upstream diagnostics are still exercised as supplied data, not product wording oracles.

The setting is shared in Tomcat's existing configuration. The saving window updates its controls immediately; other processes read on their next start. Event/timeline text is formatted by its producer when handled, rather than kept as translation descriptors; user/model content and already emitted notices are not rewritten. Static manifest contributions follow VS Code's language, not the product's independent setting. Saving uses the existing parse-and-rewrite TOML workflow: other values are preserved, comments/formatting are not guaranteed.

Settings retains successful saves only within the current connection. A new ready snapshot clears that cache and refreshes an open General page, even if only the preference or environment-override metadata changes; reconnecting disables saving. This uses existing supervisor notifications and Settings state, not a shared mutable handshake, new generation counter, or supervisor API.

Newly initialized model seeds omit product descriptions. A user-supplied description wins; otherwise built-in models render `model.description.{id}` from the catalog. Previously generated descriptions in user files are not migrated: removing that description restores the localized fallback.

Review uses the existing question workflow with `allowCustom=false`, not a separate modal/protocol. Only explicit review consent starts a reviewer. Existing plan opening and cancellation semantics remain intact. An internal answer settles the question without replacing a non-ask_question parent tool. Its original name, arguments and running status survive until the actual tool-end event; the same guard covers ready replay.

## Empty live-registry recovery (M2 finding)

```text
last live runtime closes -> release runtime/occupancy
                         -> retain only its trusted scope (key, mode, cwd)
reopen / disk listing    -> use that scope, not the deleted runtime
```

The real two-Serve test exposed `open_existing_session_slot` requiring a live base slot after deletion had legitimately closed the last one. Process cwd alone is insufficient: `NewSessionParams.cwd` can select a different project. The existing Serve registry now remembers one last-closed scope, only for its empty state; it retains neither `ChatContext` nor an occupancy guard. This preserves scope checks without a new protocol, journal, or session service.

Prior-art evidence supports separating routing context from live conversations, not copying a larger framework:
- Codex `codex-rs/app-server/src/message_processor.rs::MessageProcessorArgs` (253-255) supplies configuration/environment independently of `ThreadStateManager::new` (299).
- Continue `core/core.ts` handles `history/delete` / `history/load` (311-316) independently of IDE workspace discovery (`getWorkspaceDirs`, 182/205/805).
- VS Code `src/vs/workbench/services/workspaces/common/workspaceIdentityService.ts::WorkspaceIdentityService.getWorkspaceStateFolders` (23-40) reads `IWorkspaceContextService`, not the current editor/chat.

Counterexample/simpler alternative: only falling back to process cwd would reopen the default project but lose a non-default scope. Revisit this bounded value if Serve gains an explicit connection-level workspace context; move authority there rather than keeping two copies. Regression: `tests/serve_delete_session.test.ts` covers both refusal/reopen across two processes and closing/reopening the last non-default-scope runtime.

## Plugin timeout identity during localization

```text
pi.fetch {code,message} -> JS Error.code -> async function error string
                         -> retained JSON {code,message} -> Rust classifies code
```

`ext/dispatcher/net.rs::fetch_error_with_optional_details` already creates a structured `code`; `pi_bridge.js::toHostError` retains it, but `__pi_execute_function_async` previously discarded it with `String(e)`. `plugin_search_invoker.rs::classify_plugin_invocation_error` then classified timeouts by their English sentence. Keep that existing code/message JSON inside the existing string-only `commandFailed` channel; no new wire field, descriptor, or registry is introduced. Rust classifies the recovered `timeout` code and typed `AppError::QuickJS`; legacy opaque plugin diagnostics retain their existing compatibility fallback. The regression executes the real QuickJS bridge with an English and a Chinese timeout message, rather than bypassing the lossy boundary. The real QuickJS regression passed in task `1791561821558-q1zr1t` (4 classifier/bridge cases), alongside 6 network/credential-shape cases. If the complete plugin error channel becomes typed later, remove this string decoding and its legacy fallback instead of adding a parallel classification service.

### Exempt content

User/model prose, historical event text, externally supplied Skill/plugin descriptions, upstream diagnostic detail, machine IDs and protocol syntax, system prompts and model-side tool schemas are not translated as UI resources. Expandable raw tool output remains fixed English when it guides the model. User-facing status labels, confirmation previews, configuration help and Resume guidance remain bilingual; a technical namespace alone does not determine the reader. Preserve existing sanitization.

TS constructor-audit exemptions (source-confirmed): DOM capture/action errors in `SettingsPanel.__testingCaptureDom`, `ImagePreviewPanel.__testingCaptureDom`, `PlanPreviewEditorProvider.requirePanel`, and `PendingMessageTracker` belong to `__testing` / `__test.*` harness calls, not product UI. `extension.ts` rejects test event waiters during shutdown; `TEST_EXTRA_ARGS_ENV` parses harness-only launch options. `TomcatMessenger` malformed-NDJSON/frame diagnostics go through `onFrameError` to the development Output channel (`extension.ts`), and its invalid disposal timer is an internal API precondition. Instruction-catalog refresh errors are caught and only logged (`provider.ts::refreshInstructionCatalog`). `session_deleted` remains a machine identity. Internal router/draft consistency diagnostics and development-only asset/decode failures stay English under localized user-facing error shells.

Rust inventory classifications: user-actionable project-instruction, plugin/Skill, attachment, OAuth and session/tool errors use catalogs. These namespaces also contain model parameter guidance and developer invariants, which stay fixed English; classify by reader rather than namespace. Field/command names and HTTP reason phrases stay literal. `ndjson` parse/unknown-command prefixes, rewind failure IDs, primitive error tags and encoded warning codes are machine contracts. Plugin invocation classification uses recovered timeout codes and `AppError::QuickJS`; arbitrary diagnostics use the generic transport fallback. Chinese billing/timeout/VM phrase guesses were removed. Existing fixed-English warning/protocol tokens remain unchanged; retry budgets were not increased. `user_message_sidecar::ensure_user_message_sidecar_current` catches its internal rebuild diagnostics and only logs them; title-generation error detail is likewise swallowed/logged before a localized fallback. AST permission parsing is explicitly disabled in current production wiring (`api/chat/context.rs`, executor defaults), so its dormant parser diagnostics are not treated as active UI copy.

Model-only contracts remain literal even when a diagnostic history expander exposes their source: compaction `machine_block` control instructions/XML and `## Progress`, completion-guard nudges, and persisted-output locator markers are prompt/parse contracts, not UI headings. Their exact-marker consumers in `current_tail_guard`/`truncation` are preserved; product boundary labels already use TS catalogs. Terse `one_line_summary` key/value syntax and `overwrite`/`replace` operation tokens remain technical argument metadata. Local fallback titles are translated; the fallback branch returns an ephemeral enrichment flag so a Chinese title cannot suppress the existing utility purpose request. Model-generated titles/clauses remain content, and prompt templates stay unchanged.

## Deletion data ownership

| Data | Owner | Contract |
|---|---|---|
| sessions.json entry/current pointer | SessionManager | Remove target; same-scope fallback; serialize RMW across processes |
| transcript, user/tool-display sidecars, resume index, file baselines, exclusive preheat cache | SessionManager | Delete target files; append must not recreate transcript; report cleanup failures |
| session todo scratchpad and session-specific L0 results | Core cleanup using trusted trail root | Remove only target-owned paths; do not traverse caller-provided paths |
| pending attachment leases/blobs | Existing attachment store | Release target leases; preserve shared references and GC grace |
| draft, queue, cached view, pin | Extension Host | Retire only after acknowledged deletion or authoritative same-scope disk absence |
| workspace files, plans, shared checkpoints, audit/debug trails, shared tool-results and remote uploads | Existing owners | Not erased by Serve session deletion |

Live bound runtimes hold shared usage locks; title rewrites additionally take their own short shared guard from transcript read through rename and index rebuild. Deletion uses the existing exclusive guard and reports `session_in_use` rather than waiting. Closed but undeleted sessions can still receive titles. Late preheat-cache writes check that the main transcript exists; sidecar races remain best-effort, not a new zero-residue promise. An empty late-created lock file is allowed and must not be unlinked while another participant may hold it. CLI, Serve and detached-session compensation retain the guarded delete boundary. An absent RPC response is an unknown result, not proof of failure; retain local state until disk reconciliation.

The delete receipt is `{ warnings: string[] }`; success is already carried by the response. Missing/malformed warnings still require unknown-result reconciliation. `SlotCleanup::{Close,Delete,Shutdown}` owns cleanup strictness and registry removal; log reason strings are derived from that enum, never used to choose safety behavior. Attachment-lease cleanup ignores only NotFound; other failures reach these warnings. A subsequent fallback-open failure retains cleanup details for the same request ID, without inheriting a previous deletion's warning or rolling back committed deletion.
